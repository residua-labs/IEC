# IEC — 制度切割（institutional cuts）

[English](README.md) · **中文**

**一个制度什么时候可以改变它自己的历史、规则或权威？别人又怎样检查这个改变是否可以接纳？**

## 为什么

制度会改变自己：一个协议分叉，一个组织重新奠基，一个 agent 舰队更换自己的治理规则。这样的改变是对制度历史的一次*切割*，伴随一个后继者，可能有一次新的创世，以及对此前一切的处置。如果是非正式地做，切割正是权威被悄悄改写、历史被悄悄重新解释的地方。

IEC 让切割成为一个可以被接纳或被拒绝的对象：
- 它直接对 [MST-NF](https://github.com/residua-labs/MST-NF) 归一化；
- 它的闭合由 [RCC](https://github.com/residua-labs/RCC) 相对于一个给定的、绑定到该切割的上下文计算；
- 不可接纳的切割返回有类型的未闭合（`Await`、`Reepoch`、地址拒绝等），绝不会被悄悄接受。

Residua 自己的治理方式，即规则的改变要经过逻辑和非提案方 quorum，而不是某个人的签字，正是 IEC 要描述的那一类制度。IEC 同时也是产生 RCC 的那套"形式理论构造方法"的第二个应用，用来检验这套方法能不能推广。

## 状态（准确表述）

- **研究镜像。**IEC **不属于** Residua 的发布闭包，在它闭合之前也不会扩展。`closure_claim = 0`。
- 这里只解决了 IEC-T003（有界 profile 的分解）和相对完全闭合包；其余的定理目标（`IEC-T001` … `IEC-T038`）在 `docs/` 中只是作为目标固定下来，不是结果。
